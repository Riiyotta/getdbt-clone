## A. Form system (new, shared by T8 download form, T9 and T10)

These primitives replace HubSpot's markup. `form.download-form` (T5-T8 §A-19) should use the same primitives.

### A-1 Form card (`FormCard`)
- `div.form-container border-primary bg-blur rounded-2xl p-10`: border 1px #d1d5dc, radius 16, padding 40, bg `rgba(255,255,255,.9)` + `backdrop-filter: blur(12px)`. No shadow, no hover state.

### A-2 Field anatomy (text, email, tel, password, textarea, select)
- Field block = label row (24 tall: the label is inline 14/20 inside a 16/24 block) + control. A single-line field block is **74 tall**, a textarea block 98.

- **Control**: width 100%, height 50 (padding 12/24, 16/24 text, border 1px #d1d5dc, radius 12, transparent bg). Text colour **#6a7282** for both typed value and placeholder (there is no darker "filled" colour). No placeholder text on any field except the report-a-problem textarea (56ch).
- **Textarea**: same box, 74 tall (2 rows), native resize handle kept.

### A-5 Field states (measured on the original)

**Validation (HubSpot forms)**: runs **on blur**. Focusing and leaving an empty required field immediately (under 1.5s; no animation) adds `.invalid.error` to the control and inserts `ul.hs-error-msgs` (`margin-top: 4px`, no bullets) containing `label.hs-error-msg`: **14/20 400 #c20059**, display block, 36ch. The message wraps to 2 lines (40 tall) in a 204-wide half field and is 1 line (20) at full width, so the field block grows by 24 or 44 and the card grows with it (contact page 3118 → 3232 after blurring all 5 required fields). Optional fields never show errors on blur. Email-format and phone-format messages exist in HubSpot but were not triggered because no data was typed (see §H).
**Validation (signup)**: nothing happens on blur. It validates on submit only, which was not tested. Slot: `text-error` (#c20059) messages under fields **(inferred from the class set)**.
**Clone behaviour**: validate required fields on blur and on submit with the message style above, then show a static success state instead of submitting.

**Success state**: not reachable without submitting. The stylesheet defines `.submitted-message { text-align:center } .submitted-message p { margin-bottom:0; color:#101828 }`, so HubSpot swaps the form for a centred thank-you paragraph inside the same card. Build that: card keeps its padding, one centred 16/24 #101828 paragraph (your own text).

**reCAPTCHA**: Enterprise invisible on contact, join, launch-showcase and charts (`.hs-recaptcha {display:none}`; badge 0×0). v2 visible checkbox on signup (304×78). None on report-a-problem. The clone includes none.
